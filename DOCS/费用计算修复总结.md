# 费用计算修复总结

## 问题背景

后台使用日志中，图像生成、视频生成等记录的消耗显示为空白（`-`），需要与PH8平台的实际费用保持一致。

## 问题根因

1. **前端显示逻辑**：当 `actual_cost = 0` 且 `points_cost = 0` 时，前端显示为 `-`
2. **后端费用提取**：部分代码存在自行估算费用的逻辑，而非使用PH8返回的真实值
3. **历史数据缺失**：部分历史记录的费用字段未正确填充

## 修复内容

### 1. 后端代码修复 (`backend/routes/ph8.js`)

**移除的估算逻辑：**
- 删除了 `PH8_VIDEO_TOKEN_PRICE = 0.0000042` 的手动计算
- 删除了从请求头获取 `estimatedCost` 的逻辑
- 删除了 `totalTokens × 0.0000042` 的费用估算

**保留的费用提取逻辑：**
```javascript
// 优先从响应头提取
const costHeader = proxyRes.headers['x-ph8-cost'] || proxyRes.headers['x-cost'] || ...;

// 其次从响应体提取
ph8ActualCost = respBody.usage?.cost || respBody.usage?.price || respBody.cost || respBody.price || respBody.charge || 0;
```

### 2. 数据库历史数据修复 (`database/fix_historical_costs.sql`)

**修复逻辑：**
- 图像生成记录：设置 `actual_cost = 0.0120`, `points_cost = 12`
- 视频生成记录：设置 `actual_cost = 0.2100`, `points_cost = 210`
- 聊天记录：`points_cost = ROUND(actual_cost × 1000)`（小额免费优惠）

### 3. 前端显示逻辑 (`backend/admin/logs.html`)

**显示条件：**
```javascript
const costDisplay = (actualCost > 0 || pointsCost > 0)
    ? '显示费用'
    : '<span class="text-gray-400">-</span>';
```

## 修复流程

```

│         ↓                                                  │

│         ↓                                                  │

└─────────────────────────────────────────────────────────────┘
```

## 费用转换公式

```
积分 (points_cost) = Math.round(实际费用 × 1000)
实际费用 (actual_cost) = PH8返回的费用值（单位：元）
```

**示例：**
- PH8返回费用：¥0.0120 → 扣除积分：12
- PH8返回费用：¥0.2100 → 扣除积分：210

| 图像生成 | 12 积分 ¥0.0120 |
| 视频生成 | 210 积分 ¥0.2100 |

## 经验教训

### 1. 费用来源单一化
- 所有费用必须来自PH8 API返回值，禁止自行估算
- 避免硬编码费率，防止与PH8实际费率不一致

### 2. 字段完整性检查
- 确保 `actual_cost` 和 `points_cost` 至少有一个大于0
- 前端显示逻辑依赖这两个字段的非零判断

### 3. 数据一致性
- 定期对比PH8平台记录与本地日志
- 发现不一致时及时同步修复

### 4. 代码审查要点
- 检查是否有多处费用计算逻辑
- 确认所有费用相关代码遵循统一标准

## 部署注意事项

2. **重启服务**：`pm2 restart kbitai-api`
3. **执行脚本**：登录phpMyAdmin执行 `fix_historical_costs.sql`
4. **验证效果**：刷新后台使用日志页面确认显示正常
